## Умные указатели

* **unique_ptr**

  main создает объект через make_unique и передает его на техосмотр. Если техосчотр вызовет исключение, указатель автоматически уничтожает объект

* **shared_ptr**

  После техосмотра объекты передаются на хранение и используют shared_ptr. Это нужно чтобы например при сортировке списка можно было копировать указатели. Когда последний владелец исчезает, объект автоматически исчезает, что позволяет самому не контролировать момент удаления

* **weak_ptr**

  weak_ptr используется для витрины. Он нужен только для наблюдения, без управления объектом. Если бы тут использовался shared_ptr, то витрина бы сдерживала удаление объекта, на который она указывает, а мы хотим чтобы витрина только показывала объект, и если он был удален, то возвращала бы expired

В общем главный плюс умных указателей - это то что не нужно вручную следить за временем жизни объекта, программа автоматически этим занимается

## Исключения

Я выделил несколько видов исключений:

* **InspectionRejected**

  Вызывается, когда транспорт не проходит техосмотр (в моем коде я считаю транспорт неисправным, если в его названии содержится подстрока "broken" без учета регистра)

* **CommandError**

  Вызывается, когда команда содержит ошибку. Например, неправильный диапазон значений, неизвестный тип транспорта, неизвестная команда и т. д.

* **OfferItemError**

  Вызывается, когда ошибка возникает при взятии шлема или док-станции. Например, это может быть некорректное время аренды или некорректный возраст (отрицательные величины)

* **OfferRideError**

  Вызывается, когда ошибка возникает при взятии в аренду транспорта. Это может быть разряженный аккумулятор, не соответствие возраста (например, электросамокат могут взять только люди старше 18 лет), и т. д.

* **GetItemError**

  Вызывается, когда не получается взять требуемый объект в аренду. Например, некорректно указан id или объект уже занят

Все исключения наследуются от класса FleetError. В try catch я обрабатываю каждый вид исключения отдельно, чтобы при получении ошибки было понятно на каком этапе она возникла

## Шаблоны

Шаблоны используются для операций над объектами в хранилище, потому что иногда нам не важно какой тип объекта к нам пришел, операция будет выглядеть для всех одинаково. Например, чтобы добавить объект в хранилище, нам не обязательно знать что у него за тип, и поэтому чтобы не писать каждую функцию отдельно, я реализовал одну шаблонную.

Но когда-то нам все-таки нужна информация что именно за объект к нам пришел (например чтобы понять нужно ли нам вызывать метод для аренды вещи или для аренды транспорта), поэтому полностью шаблонами не удалось все сделать

## Креативная часть

Я добавил новый вид транспорта - SurreyBike (это многоместный четырехколесный велосипед).

Также я добавил функционал для наследников от EnergyConsumer. Теперь можно смотреть их заряд, заряжать до полного аккумулятора, и еще их заряд теперь расходуется при поездке.

Еще я добавил функционал для взятия в аренду вещей и для рассчета стоимости. Док-станция и шлем выдаются бесплатно (я подумал что шлем это скорее аксессуар к основной аренде, а док-станция нужна сотрудникам сервиса). При аренде делаются различные проверки (проверки на возраст, на количество оставшегося заряда, на то, что вещь еще не забрали и т. д.).

После окончания поездки также можно вернуть вещь обратно, чтобы ей могли пользоваться следующие.

Еще добавил несколько служебных команд, которые нужны для мониторинга состяния сервиса.

## Команды

Используются следующие параметры:

* **id** - id объекта
* **name** - имя объекта
* **energy** - потребление энергии в минуту
* **score** - оценка от 1 до 10 насколько подойдет для новичков
* **capacity** - емкость аккумулятора
* **age** - возраст
* **minutes** - на сколько минут берется аренда

Список всех доступных команд:

* `add scooter id name energy score capacity` - провести техосмотр и добавить электросамокат
* `add bike id name score` - провести техосмотр и добавить велосипед
* `add surrey_bike id name score` - провести техосмотр и добавить многоместный велосипед
* `add ebike id name energy score capacity` - провести техосмотр и добавить электровелосипед
* `add helmet id name` - добавить шлем
* `add dock id name energy capacity` - добавить док-станцию с аккумулятором
* `list` - вывести все объекты по возрастанию id, по одной строке в виде id name
* `novice` - вывести весь подходящий новичкам транспорт (score >= 6)
* `energy` - суммарное потребление энергии за минуту всех объектов
* `focus id` - выбрать позицию для витрины
* `show_focus` - вывести объект на витрине или вывести expired, если объект убрали
* `remove id` - удалить объект
* `rent id age minutes` - арендовать объект и вывести стоимость аренды
* `release id` - вернуть предмет после аренды
* `charge id` - зарядить аккумулятор объекта
* `print_charge` - вывести все объекты, потребляющие энергию, в виде id name charge
* `quit` - завершить программу
